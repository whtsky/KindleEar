# Project: KindleEar

Kindle personal push service (Python/Flask, v3.4.7): aggregates RSS/web content, builds epub/mobi/mp3, delivers to Kindle by email/WebDAV/local shelf. Entry point `main.py`; Flask app assembled in `application/__init__.py`.

## Read wiki/ FIRST — do not rescan the codebase

The `wiki/` directory is the maintained project knowledge base for LLMs (Chinese, based on v3.4.7). Consult it before exploring source files:

- `wiki/README.md` — index, quick-facts card, "where to find what" table. Start here.
- `wiki/architecture.md` — startup flow, 17 blueprints & route table, DB/task-queue/mail adapter layers.
- `wiki/project-structure.md` — full directory tree with per-file purpose.
- `wiki/data-models.md` — DB entities, dual SQL(peewee)/NoSQL(weedata) backend switching.
- `wiki/delivery-pipeline.md` — delivery/url2book/inbound-email flows + troubleshooting.
- `wiki/extensibility.md` — recipe mechanism (builtin/custom/upload), translator/TTS/summarizer/dictionary engines.
- `wiki/deployment-and-config.md` — config.py items, env-var overrides, GAE/Docker/VPS/serv00 deployment.
- `wiki/dev-guide.md` — local run, tests, i18n, gotchas.

If you discover the code has diverged from the wiki (check `__Version__` in `main.py`), verify against source and update the relevant wiki file.

## High-value warnings

- `requirements.txt` is generated by `tools/update_req.py` — never edit it directly.
- `application/lib/` is mostly vendored third-party code (calibre, readability, polyglot...) — do not treat as project business logic, avoid casual edits.
- User settings live mostly in JSON columns of `KeUser` (`base_config`/`book_config`/`custom`), not in dedicated table columns.
- Any entity change in `application/back_end/db_models.py` must work on BOTH peewee (SQL) and weedata (NoSQL) backends; schema changes need an `AppInfo.dbSchemaVersion` migration.
- `tests/runtests.py` currently hardcodes `testonly='test_inbound_email'` at the end — clear it to run the full suite.
